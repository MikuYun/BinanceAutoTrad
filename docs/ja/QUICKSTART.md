# クイックスタート

> Windows / macOS / Linux に対応。スクリーンショットの位置はあくまで目安で、実際の画面はあなたの環境に従います。

## ステップ 1：Node.js をインストールする

### すでに入っているか確認する

ターミナルを開き（Windows は **PowerShell**、macOS は「ターミナル」）、次を入力します：

```bash
node -v
```

- `v22.5.0` 以上のバージョン番号が出た → **すでにインストール済み。ステップ 2 へ進む**。
- `v18.x` / `v20.x` が出た → バージョンが低すぎるのでアップグレードが必要（本プロジェクトは Node 22.5 から使える内蔵データベースモジュールを利用しています）。
- 「コマンドが見つかりません」と出た → まだインストールされていない。

### 未インストール / バージョンが低い場合

1. <https://nodejs.org/> を開く
2. **LTS** バージョンをダウンロードする（現在は 22 系または 24 系）
3. 「次へ」を押し続けてインストールを完了する
4. **ターミナルを閉じて開き直す**（重要。そうしないと環境変数が反映されません）
5. もう一度 `node -v` を実行して確認する

> Windows では winget も使えます：`winget install OpenJS.NodeJS.LTS`
> macOS では Homebrew も使えます：`brew install node`

## ステップ 2：サービスを起動する

プロジェクトディレクトリに入り、エントリーファイルを実行します。

**Windows PowerShell：**

```powershell
cd B:\biance_trae
node server.js
```

**macOS / Linux：**

```bash
cd /你的路径/biance_trae
node server.js
```

**次のような出力が出れば成功です：**

```
══════════════════════════════════════
  币安量化终端 · U 本位永续
══════════════════════════════════════
  数据目录：B:\biance_trae\data
  监听地址：127.0.0.1:8787
  部署前缀：（站点根路径）
  实盘下单：已关闭（安全闸，只读）
  [路由] 认证 已挂载
  [行情] 数据源：币安实时行情（fapi.binance.com）
```

初回起動時には `data/` ディレクトリの下に 2 つのものが自動で作成されます：

| ファイル | 役割 |
|---|---|
| `data/app.db` | SQLite データベース。アカウント、ボット、注文、イベントを保存 |
| `data/master.key` | API Key の暗号化マスターキー（自動生成、パーミッション 0600） |

> ⚠️ **`data/master.key` は必ずバックアップしてください。** これを失うと、以前データベースに保存した API Key は二度と復号できません。

**`npm install` は不要** —— 本プロジェクトはサードパーティ依存ゼロです。

> このターミナルウィンドウがサーバーそのものです。**閉じるとサービスは停止します**。常時稼働させたい場合は
> [DEPLOY.ja.md](../../DEPLOY.ja.md) の systemd の章を参照してください。

## ステップ 3：アカウントを登録する

ブラウザで次を開きます：

```
http://127.0.0.1:8787
```

初めてアクセスするとログインページが表示されるので、上部の **「注册」**（登録）タブをクリックします：

| フィールド | 入力内容 |
|---|---|
| 用户名（ユーザー名） | 自分で決める。3〜32 文字の英字、数字、アンダースコア（例：`miku`） |
| 密码（パスワード） | 6 文字以上（覚えられない強力なものを推奨。ただし自分は覚えておくこと） |

「注册并登录」（登録してログイン）をクリックします。

> これは**純粋にローカルなアカウント**で、このマシンの `data/app.db` にのみ存在し、どこにもアップロードされません。
> メールアドレスや電話番号も不要です。パスワードを忘れた場合はデータベースを手で書き換えるしかありません（FAQ 参照）。

ログインに成功すると「概览」（概要）ページへ移動します。上部ナビゲーションは 4 項目：**概览 / 机器人 / 账户 / API Key**（概要 / ボット / 口座 / API Key）。

## ステップ 4：ペーパーモードのウォレット残高を設定する

ボットを実際に動かす前に、まずペーパーモードにお金を入れます。

1. 上部ナビゲーションの **「账户」**（口座）をクリック
2. 右上の **「设置模拟余额」**（ペーパー残高を設定）をクリック
3. 金額を入力（デフォルト 100、最小 10 USDT）
4. 「処理方式」はデフォルトの **「重置钱包，并清空所有机器人的持仓」**（ウォレットをリセットし、すべてのボットのポジションを消去）のままにする
5. 「保存」をクリック

このウォレットについて、しっかり理解しておくべきことが 3 つあります：

- これは**アカウント単位**のもので、Binance のクロス証拠金口座のウォレット残高に相当します。**すべてのペーパーボットがこの 1 つのウォレットを共有します**。
- ボットは建玉時にウォレットから**証拠金を占有**し、決済後に損益と手数料をウォレットへ**戻します**。
- 各ボットにはさらに独自の制限があります。使えるのは最大でも「このボットに割り当てた資金」までで、
  こうすることで 3 つのボットを動かしても同じ資金を 3 回重複して賭けることはありません。

> ウォレットはいつでも変更できます。ボットが一時的に 1 つもなくても変更可能です。

## ステップ 5：最初のボットを作る

上部ナビゲーションの **「机器人」**（ボット）→ 右上の **「+ 新建机器人」**（+ 新規ボット）をクリックします。

ポップアップでは 4 種類の項目を入力します：

### ① ボット名

何でも構いません。例えば `BTC 稳健型`。自分が見るためのラベルにすぎません。

### ② 取引銘柄

ドロップダウンには Binance の USDT 本位無期限契約のうち出来高上位の銘柄が、出来高順に並びます。
初心者はまず **`BTCUSDT`** か **`ETHUSDT`** を選ぶのがおすすめです（流動性が最も高く、スリッページが最小）。

### ③ 動作モード

| 選択肢 | 説明 |
|---|---|
| シミュレーションモード（不联网，本地模拟成交 / ネット接続なし、ローカルで約定を模擬） | **初心者はこれを選ぶ**。仮想資金、ローカル約定、リスクゼロ |
| 実弾モード（调用币安真实接口 / Binance の実 API を呼び出す） | 本物のお金。事前に API Key ページで鍵を設定しておく必要がある |

**初回は必ずシミュレーションモードを選んでください。**

### ④ 戦略パラメータ

フォームはパラメータ定義から自動生成され、全部で 13 項目あります。初回は**デフォルト値のままで**問題ありません：

| パラメータ | デフォルト値 |
|---|---|
| 取引方向 | 両方向 |
| このボットに割り当てる資金 | 100 USDT |
| 初回証拠金が割当資金に占める割合 | 1% |
| レバレッジ倍率 | 20 |
| 買い増し 1 回ごとの金額は前回の何倍か | 1.5 |
| 買い増し間隔 | 1% |
| 買い増しの最大回数 | 6 |
| 単方向で投入する最大金額 | 3 倍 |
| すべて買い増し完了時に、割当資金の何 % まで損失が出うるか | 35% |
| 利確方式 | 平均価格基準 |
| 利確幅 | 0.5% |
| 損切り幅 | 5% |
| 判断の実行間隔 | 5 分 |

フォームの下には **「计划预览」**（計画プレビュー）が自動で表示され、このパラメータ群がどう計算されるかを示します：

- 初回の名目金額と証拠金
- 各回の買い増しトリガー価格
- 各回の買い増し後の平均価格、利確価格、損切り価格
- ロングとショートそれぞれの強制ロスカット価格
- 買い増し完了時に最大でいくら損失が出るか

パラメータの組み合わせで実行可能な計画が算出できない場合（例：初回金額が小さすぎて発注できない）、ここに赤字の警告が直接表示され、
**どのパラメータをいくつに変えるべきか**を教えてくれます。パラメータを変更するとプレビューはリアルタイムで更新されます。

問題ないことを確認したら **「创建」**（作成）をクリックします。

## ステップ 6：起動して観察する

ボット一覧に戻り、作成したばかりのボットを探して **「启动」**（開始）をクリックします。

起動後は：

- カード上のステータスが **运行中**（稼働中）に変わる
- およそ 5 秒ごとに 1 回、判断を実行する
- 权益曲线（資産曲線）にデータが入り始める

詳細ページ（ボットカードをクリック）に入ると、リアルタイムの状況を確認できます。

## ステップ 7：詳細ページを読み解く

詳細ページは上から下へ 4 つのブロックに分かれています：

### ① 上部 KPI

| 指標 | 意味 |
|---|---|
| 現在の資産 | 割当資金 + 含み損益 + 実現損益 |
| 含み損益 | 現在のポジションのうち、まだ決済していない損益 |
| 実現損益 | すでに決済して確定した損益 |
| 建玉済みの回数 / 上限 | いま何回目か / 最大何回か |

### ② 計画プレビュー + レイヤー表

レイヤー表には各回の次が表示されます：

| 列 | 意味 |
|---|---|
| 何回目 | 1 は今建てる分、2 は最初の買い増し、以下同様 |
| この回の名目 | この回でどれだけ建てるか（名目 = 証拠金 × レバレッジ） |
| 証拠金 | この回で占有する金額 |
| 価格がここまで下がってから買い増し（ロング） | **トリガー価格 —— 実際に価格がここまで動いて初めて買い増すのであって、今建てるわけではない** |
| 買い増し後のロング平均価格 | この回を買い増した後、ポジションの平均コストがいくつになるか |
| 買い増し後のロング利確 | 買い増し後、ここまで反発したら利確する |
| 買い増し後のロング損切り | 買い増し後、ここまで下落したら損失を確定する |

すでに建てた回には **「已建」**（建玉済み）バッジが付きます。両方向モードではロングとショートの 2 つの表が同時に表示されます。

> **ここが要点**：`最多加仓 6 次`（最大 6 回買い増し）は、いま 6 回分を建てているという意味ではありません。
> いまは 1 回目だけで、残り 5 回は「価格がトリガー価格まで動いたときに初めて起きるアクション」です。

### ③ イベントログ / 注文履歴

- **イベントログ**：ボットの毎回の判断。例えば「开多 第 1 笔：名义 20.00U，保证金 1.00U」（ロング開始 第 1 回：名目 20.00U、証拠金 1.00U）、
  「平空：止盈（单层目标 81.29），盈亏 +8.05U」（ショート決済：利確（単層目標 81.29）、損益 +8.05U）、「开仓被拒：账户可用余额不足……」（建玉拒否：口座の可用残高不足……）。
  ボットが「なぜ動かないのか」を知りたいときはここを見ます。
- **注文履歴**：実際に約定した各建玉・決済の記録。数量、価格、手数料を含みます。

### ④ パラメータ編集

詳細ページの下部でパラメータを直接変更できます。変更時にはリアルタイムのプレビューがあり、「保存参数」（パラメータを保存）をクリックすると反映されます。
**稼働中のボットはパラメータを変更できません**。先に「停止」する必要があります。

## よくあるつまずき

### 「参数不可行 / 最小可下单金额」（パラメータ実行不可 / 最小発注金額）

**原因**：`割当資金 × 初回比率 × レバレッジ` で算出される初回金額が小さすぎ、取引所が許す最小発注量を下回っています。

Binance には 2 つのハードルがあります：

1. 1 回の名目金額が **≥ 5 USDT**
2. 数量は `stepSize` の整数倍であり、かつ **≥ `minQty`**

2 つ目のほうが見落としやすい。例：ある契約の価格が 976、`minQty = 0.01` のとき、
最小の「0.01 枚」でも **9.76 USDT** の価値になります —— つまり名目で 6 USDT と書いても発注できません。

プラットフォームが使っているのは：

```
最小可下单金额 = max(minNotional, ceil(minQty / stepSize) × stepSize × 现价)
```

**対処**：エラーメッセージが「分配資金」（割当資金）をいくつにすればよいか、あるいは
「第一笔保证金占比」（初回証拠金の割合）をいくつにすればよいかを直接算出してくれます。表示に従って変更すれば大丈夫です。

### 「机器人一直不动」（ボットがずっと動かない）

**これは通常、正常です。** 価格が計画上の位置まで来るのを待っているだけです。

詳細ページの「事件日志」（イベントログ）を見てください。最後の 1 件がずっと前の「建首层」（初層の構築）である、あるいは何も書かれていなければ、
価格がまだ買い増しをトリガーしておらず、利確・損切りにも達していないということです。

ログが「开仓被拒：账户可用余额不足」（建玉拒否：口座の可用残高不足）なら、ウォレットが他のボットに埋め尽くされています。
口座ページで「可用余额」（可用残高）を確認してください。

### 「行情显示不出来 / 价格不跳」（相場が表示されない / 価格が動かない）

**原因**：あなたのネットワークから Binance の `fapi.binance.com` にアクセスできません（中国国内ではよくある）。

プラットフォームは自動的にローカルの模擬価格へ降格し、ページ上で「降级」（降格）と明示します。これはクラッシュしないように設計されているためです。

**対処**：マシンにプロキシを設定するか、Binance にアクセスできるサーバーへサービスをデプロイしてください（[DEPLOY.ja.md](../../DEPLOY.ja.md) 参照）。

### 「打不开 8787 端口」（8787 番ポートが開けない）

**原因**：ポートが他のプログラムに占有されています。

**対処**：別のポートで起動します：

```powershell
# Windows PowerShell
$env:PORT=9000; node server.js
```

```bash
# macOS / Linux
PORT=9000 node server.js
```

その後 `http://127.0.0.1:9000` にアクセスします。

## 次のステップ

ペーパーモードが動いたら、この順番で進めてください：

1. **パラメータを調整する** —— [STRATEGY.md](STRATEGY.md) を読み、13 個のパラメータがそれぞれ何に影響するかを理解し、3 段階の参考設定を試す。
2. **少なくとも 2 週間はペーパーモードで動かす** —— 一方的に下落する局面も含めて、買い増しが塩漬けになる感覚を味わう。
3. **利確と損切りの理解** —— 詳細ページの「计划预览」（計画プレビュー）は、各回の利確価格と損切り価格がどう導かれるかを示してくれる。
4. **そのうえで実弾モードを検討する** —— [FAQ.md](FAQ.md) の実弾モードの章を読み、API Key を設定し（**先物取引の権限のみを有効にし、出金は絶対に有効にしない**）、
   まずはごく少額の資金で 1 週間動かす。
5. **サーバーへのデプロイを考えたい** —— [DEPLOY.ja.md](../../DEPLOY.ja.md) を読み、systemd での常駐 + Nginx リバースプロキシ + HTTPS を使う。

> もう一度繰り返します：**先物取引は極めてリスクが高く、元本をすべて失う可能性があります。** ペーパーモードでいくら稼げても、実弾モードで稼げることを意味しません。
