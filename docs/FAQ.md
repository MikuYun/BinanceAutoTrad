# 常见问题（FAQ）

> 跑起来之后最容易撞上的问题都在这。第一次上手先看 [QUICKSTART.md](QUICKSTART.md)，策略原理看 [STRATEGY.md](STRATEGY.md)，部署/HTTPS/备份看 [DEPLOY.md](../DEPLOY.md)。

## 一、安装与启动

### Q1：需要装什么？Node 版本要多高？为什么 22.5 以下不行？

只装 **Node.js**，别的都不用。要求 **≥ 22.5**，推荐 **Node 24 LTS**（`package.json` 里写着 `"engines": { "node": ">=22.5.0" }`）。

卡在 22.5 是因为程序用 Node 内置的 `node:sqlite` 存数据库，这个模块**从 22.5 才开始有**。版本低了启动会直接报：

```
Error [ERR_UNKNOWN_BUILTIN_MODULE]: No such built-in module: node:sqlite
```

检查：`node -v`。打印 `v22.5.0` 以上就合格；`v18.x`/`v20.x` 要升级；提示「找不到命令」是没装。装完记得**关掉终端重新开**，否则环境变量不生效。

### Q2：需要 `npm install` 吗？

**不需要。** 本项目零第三方依赖，连 `node_modules` 都不会生成。三条命令都能直接跑：`node server.js` 启动服务、`node scripts/check.js` 检查全部文件语法、`node --test scripts/` 跑单元测试。

### Q3：Windows 上怎么启动？

用 **PowerShell**（别用 cmd，设置环境变量的写法不一样）：

```powershell
cd B:\biance_trae
node server.js
```

看到「监听地址：127.0.0.1:8787 / 实盘下单：已关闭（安全闸，只读）」就成功了，浏览器打开 <http://127.0.0.1:8787>。macOS / Linux 同理，`cd` 到项目目录后 `node server.js`。

### Q4：端口 8787 被占用怎么办？怎么换端口？

报错里有 `EADDRINUSE` 就是被占了。两个办法：

```bash
# 办法一：找出占用者并杀掉
ss -lntp | grep 8787            # Linux/macOS，拿到 PID 后 kill
netstat -ano | findstr :8787    # Windows，再 taskkill /PID <PID> /F
```

```powershell
# 办法二（推荐）：直接换端口
$env:PORT=9000; node server.js          # Windows PowerShell
PORT=9000 node server.js                # macOS / Linux
```

换完访问 `http://127.0.0.1:9000`。

### Q5：`HOST` 是什么？为什么别人的手机访问不了？

`HOST` 默认 `127.0.0.1`，意思是**只有本机能访问**——这是安全默认值。想让局域网设备访问才改成 `0.0.0.0`，而**公网访问必须配 HTTPS 反向代理**，别把 `8787` 直接暴露出去（见 [DEPLOY.md](../DEPLOY.md) 第 5 节）。

### Q6：关掉终端窗口，服务就停了？

对，那个窗口就是服务本体，**关掉它就停了**。常驻方案：Linux 用 systemd（[DEPLOY.md](../DEPLOY.md) 第 4 节），Windows 用计划任务。

好消息是服务重启后**状态为「运行中」的机器人会自动恢复**，事件日志会写「服务重启，机器人已恢复运行」。

## 二、账号与登录

### Q7：怎么注册第一个账号？

打开首页 → 「注册」标签页 → 填两项：用户名 **3~32 位**字母/数字/下划线，密码 **6~128 位** → 点「注册并登录」，注册成功**直接登录**。

这是**纯本地账号**，只存在你自己机器的 `data/app.db` 里，不需要邮箱手机号，也不会上传到任何地方。

### Q8：忘记密码怎么办？提示「尝试次数过多」怎么办？

**没有找回密码功能**——账号数据只在你本地，没有邮箱可以验证。只有两条路：删掉 `data/app.db` 重来（会丢全部数据），或者会写代码的话直接改进数据库（密码以 `scrypt$盐$哈希` 存在 `users` 表）。**注册时就把密码记好。**

「尝试次数过多，请 N 秒后重试」是防暴力破解：**同一用户名 1 分钟内最多失败 5 次**，等提示的秒数过去再试。登录状态保持 **7 天**（Cookie 名 `bt_sid`，带 `httpOnly`，脚本读不到，防偷 Cookie）。

## 三、模拟盘

### Q9：模拟盘和实盘到底差在哪？

| | 模拟盘 | 实盘 |
| --- | --- | --- |
| 钱 | 虚拟资金，随便设 | 真的 USDT |
| 成交 | 程序本地模拟撮合 | 真实发单到币安 |
| 价格 | **和实盘同一份真实行情** | 真实行情 |
| 手续费 | 按 0.05% 固定算 | 按你的真实费率扣 |
| 滑点 | 固定 0.02% | 真实盘口深度决定 |
| 风险 | 零 | 可能亏光 |

**第一次一定先跑模拟盘**，把流程和层位表看懂再考虑实盘。

### Q10：模拟盘的价格是真的吗？

**是真的**，默认直连币安合约行情。只有当你的网络访问不了币安时，才**自动降级成本地模拟价格**并在页面提示。想强制用本地模拟价（离线演示）：`$env:BINANCE_FEED="mock"; node server.js`。

### Q11：模拟盘余额怎么改？

「账户」页 → 右上角「设置模拟余额」。规则：最小 **10 USDT**（低于会提示「模拟资金不能小于 10 USDT」），最大 **10,000,000 USDT**，开户默认 100。

⚠️ 默认处理方式是「重置钱包，并清空所有机器人的持仓」——**改余额会清掉所有模拟机器人的持仓和订单**。这个钱包是**账户级**的，所有模拟机器人共用一个余额；每个机器人再用自己那条「分配给这个机器人的资金」限制最多能动多少，避免同一笔钱被重复下注。

### Q12：模拟盘的手续费和滑点怎么算？会比实盘乐观吗？

两个写死的常数：手续费 **0.0005**（每笔名义的 0.05%，开平各一次）、滑点 **0.0002**（成交价和中间价差 0.02%）。所以一次开平往返成本约 **0.14%**——止盈只设 0.1% 的话赚的钱不够交手续费。

模拟盘是「市价单立刻全成交、滑点固定」，不考虑盘口深度不足、部分成交、极端行情拒单。**所以大仓位在模拟盘的结果会比实盘乐观**，别把模拟收益当实盘预期。

## 四、机器人与策略

### Q13：为什么建机器人报「参数不可行」？

接口会返回具体中文原因，最常见三种：

1. **第一笔太小**：第一笔名义金额低于这个交易对的最小可下单金额。例：分配资金 5 U + 第一笔 1% + 20 倍 = **1 U**，连 5 U 门槛都过不了。
2. **第一笔太重**：第一笔名义超过分配资金的 400%（如第一笔 20% × 20 倍 = 400%）。
3. **第一笔就超「单方向总投入上限」**。

机制上的原因：第一笔名义 = 分配资金 × 第一笔占比 × 杠杆。想要更大的第一笔，就**调大分配资金、调大第一笔占比，或提高杠杆**。提示里会直接算出「调到多少以上」，照改就行。

### Q14：「最小可下单金额」是什么意思？

币安对每笔订单有**两个下限**，程序取更大的那个：

```
最小可下单金额 = max(交易所最小名义额, 数量步长向上取整 × 步长 × 当前价格)
```

- **最小名义额**：多数合约 **5 USDT**。名义 = 数量 × 价格，**不是保证金**。
- **数量步长**：这个合约能下的最小数量单位，比如步长 0.01 就是最少下 0.01 个。

例：某合约价格 **976 USDT**、步长 **0.01**，最少下 0.01 个 = **9.76 USDT**，比 5 U 大，所以真实门槛是 **9.76 U**。这就是「分配资金 24 U + 第一笔 1% + 20 倍 = 4.8 U」开不出仓的原因，差一点点。

### Q15：机器人建好了，为什么一直不动作？

**大概率正常。** 它的设计就是「等价格走到计划位置才动手」：没持仓时第一个 tick 就建第一笔，之后要等价格走到**加仓线**才加仓、走到**止盈/止损线**才平仓，中间几小时没动作很正常。

去「详情」页看**事件日志**，它每一轮的判断和原因都写在里面。如果连第一笔都没建，查两件事：① 第一笔金额够不够最小可下单金额；② 模拟钱包**可用余额**够不够这笔保证金（不够会拒单，日志写「开仓被拒：账户可用余额不足」）。

### Q16：为什么层数不是一开始就满？层位表上明明写了 5 层

因为**层位表是「计划」，不是「已成交」**。程序一次只建 **1 笔**，价格真的走到下一档加仓线才加下一笔。表里每一行是「如果价格走到这里、我加上这笔，加完后的均价/止盈/止损会变成多少」的预测。

另外，**你设的层数不一定全给你**：设 6 层时程序常常只算出 5 层，因为再多加就突破了你设的「最大亏损」或「单方向总投入」上限。预览和日志会明说「层数从 6 自动降到 5」。

### Q17：「整体止盈」和「逐笔止盈」怎么选？

| 模式 | 怎么平仓 | 适合谁 |
| --- | --- | --- |
| **整体（默认）** | 等**当前实际持仓均价**达到 +止盈幅度，一次全平 | 大多数人，简单省手续费 |
| **逐笔** | 每一笔到自己入场价上方就单独平掉 | 想让前面几笔先落袋、降低持仓量的人 |

逐笔模式手续费摊得更多，也可能留下最后几笔一直在等。

### Q18：预览表里的止盈价，和我实盘看到的为什么不一样？

**故意的，而且必须这样。** 程序算止盈价用的是「**当前实际持仓的均价**」，不是「加满后的预测均价」。

如果按加满后的预测均价来算，当你只开了 1 笔时，算出的止盈价会落在现价的**错误一侧**，结果就是**开仓瞬间立刻平仓**，白交一次手续费。所以止盈必须按当前真实持仓现算。详见 [STRATEGY.md](STRATEGY.md) 第七节。

### Q19：一个账户最多几个机器人？「停止」「重置」「删除」有什么区别？

最多 **20 个**（超了报「最多创建 20 个机器人」）。操作区别：

| 操作 | 持仓 | 账本 | 什么时候用 |
| --- | --- | --- | --- |
| **停止** | 默认保留，可勾「同时平仓」 | 保留 | 临时停一下 |
| **重置** | 模拟盘清空；实盘**不平交易所仓位** | 清空，从 0 层重算 | 想重新开始 |
| **删除** | 同重置 | 连带删订单、事件、曲线 | 不要这个机器人了 |

⚠️ **实盘「重置」的坑**：只清机器人自己的账本，交易所上仓位还在。重启后这些仓位被当成「**手动仓**」，机器人不再管理——不帮你止盈也不帮你止损。

改参数必须**先停止**机器人（运行中报「请先停止机器人再修改参数」）。

## 五、实盘与 API Key

### Q20：API Key 怎么填？

币安官网 → API 管理 → 创建 API Key（选「系统生成」）→ 回本程序「API Key」页 →「添加」：备注（随便写，最长 40 字）、API Key、API Secret（**币安只显示一次**）。

保存后点「**验证**」，必须看到「验证通过，合约账户权益 X USDT」才算配好。Secret 可以先不填（状态变「待补全」），但**只填 Key 不填 Secret 读不到余额**——币安账户接口必须用 Secret 签名。

### Q21：API Key 需要开什么权限？

| 权限 | 要不要 | 说明 |
| --- | --- | --- |
| 读取（Read） | ✅ 要 | 读余额、读持仓 |
| 合约交易（Enable Futures） | ✅ 要 | 下单、撤单、设杠杆 |
| 现货交易 | ❌ 不要 | 本程序不做现货 |
| **提现（Withdraw）** | ❌ **绝对不要** | 机器人永远不需要提现 |
| IP 白名单 | ✅ 强烈建议 | 只允许你服务器的 IP |

**「禁止提现」当铁律**：Key 泄漏最坏是被乱交易，不会被直接把钱转走。

### Q22：为什么启动实盘报 `LIVE_DISABLED`？

原文：

> 实盘下单安全闸未开启：服务启动时需设置环境变量 LIVE_TRADING=1 才能启动实盘机器人。当前部署只读取行情与账户，不会向币安发送任何订单。

这是**故意的安全闸**：默认对币安完全只读，就算点了「实盘启动」也不会真下单。要真下实盘单，必须**重启服务**时带上：

```powershell
$env:LIVE_TRADING="1"; node server.js    # Windows PowerShell
LIVE_TRADING=1 node server.js            # macOS / Linux
```

启动日志会从「实盘下单：已关闭（安全闸，只读）」变成「**已开启**」。没变化说明环境变量没生效（多半用了 cmd 而非 PowerShell，或改了没重启）。

### Q23：为什么实盘账户页读不到数据？

程序不会崩，会给你具体原因：

| 页面提示 | 原因 | 怎么办 |
| --- | --- | --- |
| 尚未配置 API Key | 没添加过 | 去「API Key」页添加 |
| 缺少 API Secret | 只填了 Key | 补填 Secret |
| 已保存但尚未验证通过 | 没点验证或验证失败 | 点验证看具体报错 |
| 无法连接币安：… | 网络不通/被墙/需代理 | 见下方排查 |

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://fapi.binance.com/fapi/v1/time  # 期望 200
curl -s https://api.ipify.org; echo                                            # 出口 IP
timedatectl status                                                            # 时间要准
```

出口 IP 必须和 Key 的 IP 白名单一致，否则报 `-2015`；时间不准报 `-1021`。

### Q24：机器人会不会把我手动开的仓平掉？

**不会。** 这是全项目最小心处理的地方。

币安双向持仓模式下，同一币种的多头是**账户级聚合**的，交易所分不清哪张单是谁开的。所以程序自己在 `state_json` 里维护「本机器人自己的持仓账本」，每轮跟交易所对账：

- 交易所数量**比账本多** → 认定是手动仓，记一条「检测到 多/空 有 N 张非机器人仓位（手动仓），机器人不会动它」，然后不管。
- 交易所数量**比账本少** → 认为你手动平了一部分，账本同步缩减。

平仓也只平「自己账本里那部分数量」并带 `reduceOnly`，不可能越界。**唯一例外**：对实盘机器人点了「重置」，账本清空后交易所仓位就变成无人认领的「手动仓」，从此机器人不再管它。

### Q25：止盈止损是程序盯着平，还是挂在交易所？

程序每 **5 秒**检查一次价格（这个间隔可以用环境变量 `TICK_INTERVAL_MS` 调），到价就主动市价平；实盘**同时**还会同步挂 `TAKE_PROFIT_MARKET` / `STOP_MARKET` 条件单（触发价用标记价格），每 60 秒对账撤旧挂新。两条腿都走的意义是：**程序挂了、网断了、电脑关机了，交易所上还留着保护单**。条件单只覆盖机器人自己那部分数量，不碰手动仓；挂不上会记事件，不会静默失败。

### Q26：要开「双向持仓模式」吗？服务器重启后仓位还在吗？

**要开。** 程序按双向持仓发单：做多带 `LONG`、做空带 `SHORT`。币安合约界面 → 右上设置 →「持仓模式」→ 双向持仓（切换前必须先平掉所有仓位）。

重启后：**机器人**自动恢复；**仓位**一直在交易所（重启不会平仓）；**账本**存在数据库里，接着用，不会把自己开的仓当手动仓。

## 六、报错代码对照表

### Q27：币安那些 `-1xxx` 到底什么意思？

| 代码 | 人话 | 程序怎么处理 | 你要做什么 |
| --- | --- | --- | --- |
| `-1021` | 时间戳超出允许范围 | 自动重新校准并重试一次 | 校系统时间 |
| `-1022` | 签名不对 | 重新校准后重试一次 | 重新粘贴 Secret |
| `-1111` | 数量小数位太多 | 自动降精度重发 | 一般不用管 |
| `-4164` | 金额/精度不达标 | 同 `-1111` | 调大第一笔金额 |
| `-1106` | 不该带 reduceOnly 却带了 | 已按持仓模式规避 | 查币安持仓模式 |
| `-2019` | 保证金不足 | 不翻译，原文透出 | 降杠杆、调小仓位 |
| `-2015` | Key 错/没权限/IP 不符 | 提示「API Key 或 Secret 错误，或密钥没有合约账户读取权限」 | 查权限和 IP 白名单 |
| `-1003` | 请求太频繁被限频 | 记错误，下轮再试 | 少开机器人、调大周期 |
| `-1007` | 服务器超时，不知成交没 | 用订单号回查，不重复下单 | 一般不用管 |
| `-4046` | 重复设置同一参数 | 视为成功（杠杆已是目标） | 不用管 |
| `-2013` | 订单不存在 | 认为已平，同步账本 | 一般不用管 |

### Q28：`-1021` / `-1022` 时间戳和签名错误

**原因**：币安要求每个请求带时间戳，且必须在 `recvWindow`（本项目 5000 毫秒）内。本机时间偏差几秒就会判超时。

**程序**：后台每 60 秒跟币安对时，遇到 `-1021`/`-1022` 会**强制重新校准再重试一次**。

**你**：一直报说明本机时间真歪了——Linux 跑 `sudo timedatectl set-ntp true`，Windows 在「设置→时间和语言→立即同步」。时间没问题还报 `-1022`，基本是 **Secret 贴错了**（多空格、少字符）。

### Q29：`-1111` / `-4164` 精度错误

**原因**：币安规定每个合约数量最少保留几位小数，比如步长 0.01 时下 0.019 会被拒。

**程序**：按该合约真实的 `stepSize` **逐档降精度重发**，通常第一次就成功，正常情况你看不到这个错。

**你**：`-1111` 反复出现，多半是精度规则没拉到（网络问题用了兜底值）——删掉 `data/rules-cache.json` 重启服务重新拉。`-4164` 反复出现通常不是精度而是**这笔金额真的太小**，去调大分配资金或第一笔占比。

### Q30：`-1106` reduceOnly 相关

**原因**：`reduceOnly` 是「只减仓不开新仓」标记。币安规定**双向持仓模式下传它会被直接拒绝**，只有单向持仓才需要。

**程序**：已区分好——双向持仓（`positionSide` 为 `LONG`/`SHORT`）**不传**，单向持仓才传。

**你**：还撞到就检查币安那边的持仓模式是不是被切成「单向持仓」了，切回双向。

### Q31：`-2019` 保证金不足

**原因**：可用于开这一笔的保证金不够。「不够」不一定是没钱——可能是被其他仓位占住了，也可能是这个机器人自己把预算用完了。

**程序**：这个错误**没有专门翻译**，币安英文原文直接透出（形如「币安接口错误：Margin is insufficient.」）。

**你**（按顺序）：① 看「账户」页可用余额够不够这笔保证金；② 调小「第一笔保证金占比」或降低杠杆（注意**杠杆越低，同样名义占用的保证金越多**）；③ 检查是不是同时开了好几个机器人把保证金吃干净了；④ 实盘账户里已有的手动仓也占保证金，可能不是程序的问题。

## 七、安全

### Q32：API Key 存在哪里？安全吗？

存在本地 `data/app.db` 里，**不是明文**：

| 项目 | 做法 |
| --- | --- |
| 加密算法 | **AES-256-GCM**（带完整性校验，篡改会被发现） |
| 密钥来源 | `data/master.key`（32 字节随机数，权限 `0600`） |
| 界面显示 | 只显示打码 Key（前 4 位 + 星号 + 后 4 位） |
| 登录密码 | `scrypt` + 每用户独立随机盐哈希 + 恒定时间比较 |

**拿到数据库文件但没有 `master.key`，也解不开 Key。**

### Q33：`data/master.key` 丢了会怎样？

**已经存进去的 API Key 永远解不开。** 表现：机器人能启动，但一列 Key 就报解密失败。

- **有备份**：把 `master.key` 和 `app.db` **一起**还原（必须是一对，换了任一个都对不上）。
- **没备份**：只能删掉旧 Key 重新录一遍，`master.key` 会自动重新生成。也可以用环境变量 `BT_MASTER_KEY`（64 位十六进制）固化密钥，但环境变量在服务器上其他进程能看到。**唯一稳妥的做法：备份时把 `data/` 整个拷走。**

### Q34：能放到公网用手机访问吗？一定要 HTTPS 吗？

**能，但必须做两件事**：① 前面加 **HTTPS 反向代理**（Nginx + 证书），Node 继续只听 `127.0.0.1`；② 防火墙只开 22/80/443，`8787` 绝不要直接暴露公网。

**为什么必须 HTTPS**：登录密码和 API Key 都是走 HTTP 请求体传的，HTTP 是明文，同一个 WiFi 下的人、路上的节点都能看到。配置方法见 [DEPLOY.md](../DEPLOY.md) 第 5 节。

### Q35：`data/` 目录能提交到 git 吗？

**绝对不能。** 里面有 `app.db`（含加密 Key、密码哈希）和 `master.key`（解密密钥），两个一起泄露 = Key 直接可用。

注意 SQLite 是 WAL 模式，`data/` 下会同时有 `app.db`、`app.db-wal`、`app.db-shm`，**备份/拷贝要一起拷**，只拷 `app.db` 可能丢掉最近的写入。

## 八、部署与运维

### Q36：怎么让它在服务器上一直跑？

Linux 上用 **systemd** 托管，开机自启、崩了自动重启。完整 unit 文件见 [DEPLOY.md](../DEPLOY.md) 第 4 节。要点：unit 里写对环境变量（`HOST`/`PORT`/`LIVE_TRADING`），`WorkingDirectory` 必须指向项目根目录，否则 `data/` 会建到别的地方。

### Q37：怎么配反向代理和 HTTPS？

见 [DEPLOY.md](../DEPLOY.md) 第 5 节（Nginx 配置、certbot 证书、子路径部署要设 `BASE_PATH`）。最容易踩的坑：反代必须透传 `Host` 和 `X-Forwarded-Proto` 头，否则后端把 HTTPS 请求当 HTTP，登录状态会莫名掉线。

### Q38：怎么备份、怎么升级和回滚？

**备份 `data/` 整个目录**，尤其 `app.db`（账号/机器人/订单/历史）和 `master.key`（丢了 Key 全作废）。建议每天定时打包异地存一份，升级前先备份。备份文件本身也是敏感数据，别传公开网盘或 git 仓库。升级/回滚流程见 [DEPLOY.md](../DEPLOY.md) 第 7 节。

## 九、还是没解决？

按顺序看：① **机器人详情页的事件日志**——程序每一步的想法都写在这里，九成问题能直接看出原因；② **终端/服务日志**（`journalctl -u <服务名> -n 100 --no-pager`）；③ [DEPLOY.md](../DEPLOY.md) 第 8 节故障排查；④ 去项目仓库提 Issue。

> ⚠️ 贴日志时记得**删掉** API Key、Secret、服务器 IP、账号密码。
