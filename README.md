## 这是什么

### 一句话版本

你用网页给它设置几个参数（本金多少、跌多少加一次仓、赚多少跑），
它就自己盯着行情，**跌了按计划一笔笔加仓把成本摊低，等价格反弹回来有赚就全部止盈**，然后重新开始下一轮。

### 举个例子（不是承诺收益，只是说明机制）

假设你给它分配 100 USDT、20 倍杠杆：

| 发生什么 | 机器人做什么 |
|---|---|
| 价格 100，开始盯 | 开第 1 笔多单，名义 20U |
| 价格跌到 99（跌 1%） | 加第 2 笔，名义 30U —— 平均成本被拉低 |
| 价格跌到 98（再跌 1%） | 加第 3 笔，名义 45U —— 平均成本又低了 |
| 价格反弹回平均成本 +0.5% | **全部止盈平仓**，这一轮结束，等下一次机会 |
| 价格继续跌，还没反弹 | 继续按计划加仓，直到用完「层数上限」 |
| 跌太多，超过设置的止损 | 认亏平仓，不再加 |

同时它还会在**反方向**开一份对称的空单（可以关掉），这样涨跌都有机会。

> 这套逻辑在圈里没有统一叫法，可以理解为「**定点加仓 + 均价止盈**」，
> 也可以理解成只朝一个方向开火的网格。

### 和常见「网格机器人」的区别

| | 普通网格 | 本项目 |
|---|---|---|
| 加仓方向 | 涨跌都挂单，双向都摊 | 只在亏损方向加仓摊成本（可双向各一份） |
| 平仓条件 | 每一格各自独立止盈 | **按当前实际持仓均价整体止盈**（也可以改成逐笔止盈） |
| 层数 | 一上来就挂满全部格子 | **只先开第 1 笔，之后按真实行情一笔笔加** |
| 资金 | 全部资金都在里面 | 每个机器人只动用「分配给它」的那一份资金，赚了才按比例放大 |

### 几个特点

- **零第三方依赖** —— 只用 Node.js 内置模块，`npm install` 都不需要。不用担心供应链投毒。
- **自带网页界面** —— 不用写一行代码、不用改配置文件，全在浏览器里点。
- **模拟盘先练手** —— 本地虚拟资金、本地撮合，不碰真钱，随时可以改余额重来。
- **实盘可开关** —— 配好 API Key 就能连真实账户；默认**关闭**，必须显式打开才会真的下单。
- **参数全量纲化** —— 代码里没有任何写死的金额，同一套参数在 100U 和 10000U 账户上行为完全等比。

## 适合谁、不适合谁

### 适合

- 想学量化交易，**不想先啃一堆金融工程书**的人 —— 有界面、有模拟盘，点几下就能看到机器人在干什么。
- 手工做「跌了补仓、回本就走」已经有经验，想把这件事**自动化**的人。
- 想读一份**完整、能跑、零依赖**的 Node 项目源码的人（约 1.1 万行，注释齐全）。
- 想拿它当**骨架**，改成自己的策略的人（策略层是纯函数，好替换）。

### 不适合

- 想要「稳定月化 20%」的人 —— **没有这种东西**。见下面的风险提示。
- 想要高频、毫秒级抢跑的人 —— 这是 5 秒一次决策的中低频策略。
- 完全不懂合约、不知道「杠杆」「强平」是什么的人 —— 请先去看 [docs/STRATEGY.md](docs/STRATEGY.md)，或者先在模拟盘玩一周。
- 想要一套「托管服务」的人 —— 这是你自己部署在自己机器上的工具，没有云端、没有账号体系共享。

## 界面长什么样

启动后浏览器打开 `http://127.0.0.1:8787`，注册一个本地账号即可。一共 5 个页面：

| 页面 | 你能看到 / 能做什么 |
|---|---|
| **登录 / 注册** | 本地账号，密码加盐哈希存储 |
| **概览** | 账户权益、今日盈亏、正在跑的机器人、订单数、实时行情榜、权益曲线图 |
| **机器人** | 新建（参数表单自动生成）、启动、停止、重置、删除 |
| **机器人详情** | 计划预览（几层 / 每层多少钱 / 多空各自的强平价和止盈止损）、层位表、事件日志、订单流水、改参数实时预览 |
| **账户** | 模拟盘 / 实盘权益、持仓明细、**模拟盘余额可随时改**、实盘不可用时显示提示 |
| **API Key** | 添加、验证、删除；密文落库，页面只显示打码后的值 |

## 3 分钟跑起来

### 前置：装 Node.js

需要 **Node.js ≥ 22.5**（本项目用了 `node:sqlite` 内置数据库），推荐直接用 **Node 24 LTS**。

```bash
node -v     # 打印 v22.5.0 或更高才行
```

没装的话去 <https://nodejs.org/> 下载 LTS 版，一路下一步即可。

### 启动

**Windows（PowerShell）：**

```powershell
cd B:\biance_trae
node server.js
```

**macOS / Linux：**

```bash
cd /path/to/biance_trae
node server.js
```

看到类似输出就成功了：

```bash
══════════════════════════════════════
  币安量化终端 · U 本位永续
══════════════════════════════════════
  数据目录：B:\biance_trae\data
  监听地址：127.0.0.1:8787
  部署前缀：（站点根路径）
  实盘下单：已关闭（安全闸，只读）
  [路由] 认证 已挂载
  [行情] 数据源：币安实时行情（fapi.binance.com）
```

> **不需要 `npm install`** —— 本项目零第三方依赖。

### 第一次使用

1. 浏览器打开 <http://127.0.0.1:8787>，点「注册」，随便填个用户名密码（只存在你本机）。
2. 进「机器人」页 → 点「新建机器人」 → 选币种（比如 `BTCUSDT`）→ 模式选 **模拟盘（paper）**。
3. 参数保持默认就能用，点「创建」。
4. 回到列表点「启动」，然后进详情页，你就能看到它开始工作了：事件日志、订单流水、权益变化。

> 想改模拟盘的钱？去「账户」页点「设置模拟余额」按钮。这个钱包是**所有模拟机器人共用**的，
> 开仓时从里面占用保证金，平仓后把盈亏和手续费退回钱包，机器人之间不会互相抢钱。
> 每个机器人再各自占用自己「分配到的资金」，不会互相抢钱。

### 换个端口 / 让局域网能访问

```powershell
# Windows PowerShell
$env:PORT=9000; node server.js

# macOS / Linux
PORT=9000 node server.js
```

## 它是怎么工作的

每 **5 秒**（可调）循环一次，做这几件事：

```
① 取行情          从币安拉最新价、ATR 波动率、K 线
      ↓
② 算钱            资金基数 = 分配资金 + 这个机器人累计赚到的钱
      ↓
③ 算计划          首笔多少、加仓几次、每层多少、止盈价多少、止损价多少
      ↓
④ 做决策          现在是该开首笔？该加仓？该止盈？该止损？还是什么都不做？
      ↓
⑤ 执行            模拟盘：本地记账   实盘：真的发单到币安
      ↓
⑥ 落库            写订单、写事件、记权益曲线
```

### 三个关键设计

**1. 价格锚点（anchorPrice）**
计划一旦生成，加仓的触发价就固定下来，不会随着行情上下漂移。
只有「完全平仓」之后才会重新取锚点、开新一轮。

**2. 止盈价永远按「当前实际持仓均价」现算**
`止盈价 = 当前均价 × (1 + 止盈幅度)`

为什么强调「当前」？因为如果按「加满 6 层之后的预测均价」去算，只开了 1 笔的时候，
那个预测均价还在很下面（多单），现价早就高过它了 —— 结果就是**一开仓立刻止盈**，白交手续费。
这是这个项目早期踩过的一个真实坑，现在改成了现值计算。

**3. 层数是「最多能加几次」，不是「一开始开几层」**
`maxLayers = 6` 的意思是：先开 1 笔，之后行情每走 `间距` 就加一次，最多加到 6 笔。
不是一上来就把 6 笔全开了。

## 参数怎么调

13 个参数全部中文，表单里直接填。默认值就是一套「中性」配置：

| 参数 | 含义 | 默认 |
|---|---|---|
| 交易方向 | 双向 / 只做多 / 只做空 | 双向 |
| 分配给这个机器人的资金 | 它最多能动用的本金（USDT） | 100 |
| 第一笔保证金占分配资金的比例 | 第 1 笔用本金的百分之几 | 1% |
| 杠杆倍数 | 合约杠杆 | 20x |
| 每加一次仓，金额是上一次的几倍 | 加仓递增倍率 | 1.5 |
| 加仓间距 | 价格相对均价走多少 % 加一次 | 1% |
| 最多加仓几次 | 层数上限 | 6 |
| 单方向最多投入多少钱 | 名义上限 = 分配资金 × 这个倍数 | 3 |
| 全部加满时，最多能亏分配资金的百分之几 | 风险预算 | 35% |
| 止盈方式 | 按均价整体止盈 / 逐笔止盈 | 按均价 |
| 止盈幅度 | 相对当前均价赚多少 % 就跑 | 0.5% |
| 止损幅度 | 相对当前均价亏多少 % 就认亏 | 5% |
| 每多久判断一次 | 决策周期 | 5 分钟 |

### 三档参考配置

| | 保守 | 中性（默认） | 激进 |
|---|---|---|---|
| 第一笔保证金占比 | 0.5% | 1% | 2% |
| 杠杆 | 5x | 20x | 50x |
| 加仓间距 | 2% | 1% | 0.5% |
| 最多加仓 | 4 次 | 6 次 | 10 次 |
| 单方向名义上限 | 2 倍 | 3 倍 | 6 倍 |
| 最多亏损 | 20% | 35% | 50% |

> **激进档不是「更赚」，是「更快归零碎掉」。** 新手直接用默认值，跑够两周模拟盘再谈调参。

每个参数调大调小分别会发生什么，见 [docs/STRATEGY.md](docs/STRATEGY.md)。

## 模拟盘与实盘

| | 模拟盘（paper） | 实盘（live） |
|---|---|---|
| 需要 API Key | 不需要 | **必须**先添加并验证 |
| 钱 | 本地虚拟余额，随便改 | 币安账户里的真钱 |
| 成交 | 本地撮合，扣 0.05% 手续费 + 0.02% 滑点 | 真实市价单 |
| 风险 | 零 | **会真的亏钱** |
| 用途 | 学界面、练参数、验证逻辑 | 只在你完全清楚后果时用 |

### 开实盘的两道门

1. **必须有已验证的 API Key** —— 没配会被拒绝启动，并给中文提示。
2. **必须启动时设置环境变量 `LIVE_TRADING=1`** —— 否则即使 Key 配好了，实盘机器人也会被拦下来，只读行情、不下单。

```powershell
# Windows PowerShell
$env:LIVE_TRADING=1; node server.js

# macOS / Linux
LIVE_TRADING=1 node server.js
```

### 机器人不会平掉你手动开的仓

币安的双向持仓是**账户级聚合**的 —— 接口只告诉你「这个币我有多单 4.37 张」，
分不清哪几笔是机器人开的、哪几笔是你手动开的。

本项目的做法：给每个实盘机器人记一本**自己的持仓账本**。

- 机器人开仓成功 → 记进账本
- 每次 tick 跟交易所实际持仓对账
- 交易所数量**多于**账本 → 多出来的当**手动仓**，标出来，**绝不平它**
- 你在币安上手动平了 → 账本按比例缩减，不会去平不存在的仓位

所以手动仓和机器人仓可以共存。

### 创建实盘机器人时，已有持仓要你决定怎么处理

**这是 1.0.1 修的一个严重 bug**：早期版本没有记录「哪些仓是你原来就有的」，
每轮对账都在重新猜。结果可能出现两种情况：

- 机器人以为交易所上那一堆全是你手动开的 → 自己只认一小笔，**账户大仓、机器人小仓**
- 你手动把仓全平了 → 机器人账本被静默清空 → 下一轮它以为「我没仓」，**又开一笔**

现在创建实盘机器人时，如果你选的交易对已经有持仓，会先查一次并弹出提示：

| 选项 | 行为 |
|---|---|
| **不保留，从零开始**（推荐） | 机器人完全无视你现有的仓，只按自己开的仓算。你的仓要自己平，机器人不动它 |
| **保留为「手动仓」** | 把当前持仓登记为**基准快照**，之后机器人照常按参数运行，但**永远不用这部分仓位计算加仓量、均价、止盈价**。详情页顶会一直显示「手动仓基准 多 X / 空 Y 张（不参与计算）」 |

选了「保留」还会在**首次启动时重拍一次基准**（因为创建到真正启动可能隔了很久，仓位早变了）。
如果机器人已经有自己的仓位，就不会重拍 —— 否则会把机器人的仓当成手动仓。

另外，以前你手动把含机器人那份的仓全平掉时，机器人是**静默**清账本的；现在会写一条明确警告：

> 对账：多单在交易所已归零，但机器人账本里还有 1.234567 张。说明你手动把这个方向的仓（含机器人的部分）平掉了……

## 安全设计

| 项 | 做法 |
|---|---|
| API Key 存储 | **AES-256-GCM 加密**后落库，任何接口都不回传明文，页面只显示打码值 |
| 加密主密钥 | `data/master.key`（自动生成，权限 0600）；也可用环境变量 `BT_MASTER_KEY` 提供 |
| 登录密码 | **scrypt + 每用户随机盐**，校验用 `timingSafeEqual` 防时序攻击 |
| 会话 | `HttpOnly; SameSite=Lax` Cookie，7 天过期，服务端可清除 |
| 登录限流 | 同一用户名 5 次/分钟 |
| SQL | 全部参数绑定，无字符串拼接 |
| 权限 | 所有写接口都校验资源归属，A 用户改不了 B 用户的机器人 |
| 网络暴露 | **默认只听 `127.0.0.1`**，不对外 |
| 实盘下单 | **默认关闭**，`LIVE_TRADING=1` 才放开 |
| 重复下单 | 确定性 `clientOrderId`，网络超时重发会被交易所按重复 id 拒掉 |

> ⚠️ **`data/master.key` 丢了，已存的 API Key 就解不回来了。**
> 备份 `data/app.db` 时必须**连着 master.key 一起备份**，单独备份数据库等于白备。

完整安全策略见 [SECURITY.md](SECURITY.md)。

## 风险提示（一定要读）

这是一个**真实的、会亏钱的交易工具**。请先读完这段再决定要不要上实盘。

1. **合约是保证金交易，会爆仓。** 20 倍杠杆下，价格反向走 5% 就可能让你损失全部本金。杠杆越高，越容易归零。
2. **「加仓摊低成本」在单边行情里会一路被套。** 这个策略的核心假设是「价格会反弹」。
   如果某个币进入长期单边下跌，加仓只会让你**亏得更多更快**，直到用完层数或打止损。
3. **参数越激进，归零越快。** 高杠杆 + 窄间距 + 多层数 = 极短时间内爆仓的配方。
4. **手续费是持续的摩擦成本。** 每次开平仓都要交手续费，止盈幅度设太小（比如 0.1%）时，
   手续费会吃掉大部分利润甚至倒亏。
5. **强平价是估算值**，实际以交易所返回为准。
6. **本项目按 Apache-2.0 「原样」提供，不附带任何担保。** 作者不对任何使用本项目造成的资金损失负责。

**如果你打算上实盘，请遵守这个顺序：**

1. 模拟盘跑 **至少两周**，确认逻辑和参数自己能接受。
2. 上实盘先用**你完全亏得起的极小资金**，跑一周。
3. API Key **只开合约交易权限，绝对不要开提现权限**，有条件就绑定 IP 白名单。
4. 每天检查一次账户，确认机器人行为符合预期。
5. 任何时候觉得不对，先**停机器人**，再分析。

## 常见问题

**Q：需要 `npm install` 吗？**
不需要。零第三方依赖，只用 Node 内置模块。

**Q：Node 版本要多高？为什么 22.5 以下不行？**
本项目用 `node:sqlite` 做数据库，这个模块从 **Node 22.5** 才开始提供。低于这个版本启动会直接报错。

**Q：能放到公网让手机访问吗？**
能，但**必须走 HTTPS 反向代理**，并且不要直接把端口暴露到公网。
详见 [DEPLOY.md](DEPLOY.md)。

**Q：模拟盘的价格是真的吗？**
是真的。默认直连币安 `fapi.binance.com` 拉实时行情。只有在你网络访问不了币安时，才会自动降级成本地模拟价格并在页面提示。

**Q：为什么创建机器人报「参数不可行」？**
多半是「分配资金 × 第一笔占比 × 杠杆」算出来的第一笔金额太小，低于交易所的最小下单要求。
提示里会直接告诉你需要把哪个参数调到多少。详见 [docs/FAQ.md](docs/FAQ.md)。

**Q：机器人一直不动作？**
正常。它在等价格走到计划的位置。跑到「详情」页看事件日志，能看到它每一步的判断。

更多问题见 [docs/FAQ.md](docs/FAQ.md)。
