# バイナンス自動売買ボット · BinanceAutoTrad

> ウェブ画面を備えたバイナンス先物ボット：**下落したら数回に分けて買い増して平均単価を下げ、反発して利益が出たら利確**。
> ペーパーモードと実弾モードに対応、**サードパーティ依存ゼロ**、コマンド 1 本で起動。

## これは何か

### ひとことで言うと

あなたはウェブ画面でいくつかのパラメータ（元手はいくらか、何 % 下がったら 1 回買い増すか、何 % 稼いだら逃げるか）を設定するだけ。
あとはボットが自分で相場を見張り、**下落したら計画どおりに 1 筆ずつ買い増してコストを下げ、価格が反発して利益が出たらまとめて利確**し、そのあと次のラウンドを始めます。

### 例（収益の約束ではなく、仕組みの説明です）

100 USDT を割り当て、レバレッジ 20 倍で動かすとします：

| 起きること | ボットの動作 |
|---|---|
| 価格 100 で監視開始 | 1 筆目のロングを建てる。名目 20U |
| 価格が 99 に下落（1% 下落） | 2 筆目を追加、名目 30U —— 平均コストが下がる |
| 価格が 98 に下落（さらに 1% 下落） | 3 筆目を追加、名目 45U —— 平均コストがさらに下がる |
| 価格が平均コスト +0.5% まで反発 | **すべて利確して決済**。このラウンドは終了し、次の機会を待つ |
| 価格が下がり続け、まだ反発しない | 計画どおり買い増しを続け、「層の上限」を使い切るまで続ける |
| 下落しすぎて設定した損切りを超える | 損失を認めて決済し、それ以上は買い増さない |

同時に**逆方向**へ対称のショートも建てます（オフにできます）。これで上げても下げても機会があります。

> このロジックには界隈で統一された呼び方がありません。「**定点買い増し + 平均単価での利確**」と
> 理解してもいいですし、一方向にだけ撃つグリッドと理解しても構いません。

### 一般的な「グリッドボット」との違い

| | 一般的なグリッド | 本プロジェクト |
|---|---|---|
| 買い増しの方向 | 上げ下げ両方に注文を置き、両方向でコストをならす | 損失方向にだけ買い増してコストを下げる（両方向それぞれ 1 本も可） |
| 決済条件 | 各グリッドが個別に利確 | **現在の実際の保有平均単価で全体を利確**（1 筆ずつの利確にも変更可） |
| 層数 | 最初から全グリッドを発注 | **まず 1 筆目だけ建て、その後は実際の相場に応じて 1 筆ずつ追加** |
| 資金 | 全資金が中に入っている | 各ボットは「割り当てられた」分だけを使い、利益が出てから比率に応じて拡大 |

### 特徴

- **サードパーティ依存ゼロ** —— Node.js の組み込みモジュールだけを使い、`npm install` すら不要。サプライチェーン汚染の心配がありません。
- **ウェブ画面を内蔵** —— コードを 1 行も書かず、設定ファイルも触らず、すべてブラウザ上で操作できます。
- **まずペーパーモードで練習** —— ローカルの仮想資金・ローカル約定で、実際のお金には触れません。残高はいつでも変更してやり直せます。
- **実弾モードはオン/オフ可能** —— API Key を設定すれば実際の口座に接続できます。既定では**オフ**で、明示的にオンにしない限り実際の発注は行いません。
- **パラメータはすべて次元化済み** —— コードに金額のハードコードは一切なく、同じパラメータが 100U の口座でも 10000U の口座でも完全に比例した挙動になります。

## 向いている人と向いていない人

### 向いている人

- クオンツ取引を学びたいが、**金融工学の本を山ほど読むのは避けたい**人 —— 画面とペーパーモードがあり、数クリックでボットの動作を確認できます。
- 「下がったら買い増し、戻ったら逃げる」を手作業でやった経験があり、それを**自動化**したい人。
- **完全で、実際に動き、依存ゼロ**の Node プロジェクトのソースを読みたい人（約 1.1 万行、コメント充実）。
- これを**骨組み**にして自分の戦略に作り替えたい人（戦略層は純粋関数なので差し替えが容易）。

### 向いていない人

- 「安定して月利 20%」を求める人 —— **そんなものはありません**。下のリスクの項を読んでください。
- 高頻度・ミリ秒単位の先回りをしたい人 —— これは 5 秒に 1 回判断する中低頻度の戦略です。
- 先物をまったく理解せず、「レバレッジ」「強制ロスカット」が何か分からない人 —— まず [docs/STRATEGY.md](docs/ja/STRATEGY.md) を読むか、ペーパーモードで 1 週間遊んでください。
- 「ホスティングサービス」を求める人 —— これは自分のマシンに自分でデプロイするツールです。クラウドも、アカウントを共有する仕組みもありません。

## 画面のイメージ

起動したらブラウザで `http://127.0.0.1:8787` を開き、ローカルアカウントを登録するだけ。ページは全部で 5 つです：

| ページ | 見えるもの / できること |
|---|---|
| **ログイン / 登録** | ローカルアカウント。パスワードはソルト付きハッシュで保存 |
| **概览**(概要) | 口座エクイティ、当日の損益、稼働中のボット、注文数、リアルタイム相場ランキング、エクイティ曲線 |
| **机器人**(ボット) | 新規作成（パラメータフォームは自動生成）、起動、停止、リセット、削除 |
| **机器人详情**(ボット詳細) | 計画プレビュー（何層 / 各層いくら / ロング・ショートそれぞれの強制ロスカット価格と利確・損切り）、層テーブル、イベントログ、注文履歴、パラメータ変更のリアルタイムプレビュー |
| **账户**(口座) | ペーパー / 実弾のエクイティ、ポジション明細、**ペーパー残高はいつでも変更可**、実弾が使えないときは案内を表示 |
| **API Key** | 追加、検証、削除。暗号文で DB に保存し、画面にはマスク後の値だけを表示 |

## 3 分で動かす

### 前提：Node.js をインストール

**Node.js ≥ 22.5** が必要です（本プロジェクトは組み込みデータベース `node:sqlite` を使用）。**Node 24 LTS** をそのまま使うのがおすすめです。

```bash
node -v     # 打印 v22.5.0 或更高才行
```

未インストールなら <https://nodejs.org/> から LTS 版をダウンロードし、「次へ」で進めるだけです。

### 起動

**Windows（PowerShell）：**

```powershell
cd B:\biance_trae
node server.js
```

**macOS / Linux：**

```bash
cd /path/to/biance_trae
node server.js
```

次のような出力が出れば成功です：

```bash
══════════════════════════════════════
  币安量化终端 · U 本位永续
══════════════════════════════════════
  数据目录：B:\biance_trae\data
  监听地址：127.0.0.1:8787
  部署前缀：（站点根路径）
  实盘下单：已关闭（安全闸，只读）
  [路由] 认证 已挂载
  [行情] 数据源：币安实时行情（fapi.binance.com）
```

> **`npm install` は不要** —— 本プロジェクトはサードパーティ依存ゼロです。

### 初回の使い方

1. ブラウザで <http://127.0.0.1:8787> を開き、「注册」(登録) をクリックして、適当なユーザー名とパスワードを入力します（あなたのマシンにだけ保存されます）。
2. 「机器人」(ボット) ページへ → 「新建机器人」(ボットを新規作成) をクリック → 通貨ペアを選択（例えば `BTCUSDT`）→ モードで **模拟盘（paper）**(ペーパーモード) を選択。
3. パラメータは既定値のままで使えるので、「创建」(作成) をクリック。
4. 一覧に戻って「启动」(開始) をクリックし、詳細ページへ進めば稼働が始まっています：イベントログ、注文履歴、エクイティの変化が見えます。

> ペーパーモードの資金を変えたい？ 「账户」(口座) ページで「设置模拟余额」(ペーパー残高を設定) ボタンをクリックします。このウォレットは**すべてのペーパーボットで共有**され、
> 建玉時にここから証拠金を確保し、決済後に損益と手数料をウォレットへ戻します。ボット同士が資金を取り合うことはありません。
> 各ボットはさらに自分が「割り当てられた資金」を個別に確保するので、やはり互いに奪い合いません。

### ポートを変える / LAN からアクセスできるようにする

```powershell
# Windows PowerShell
$env:PORT=9000; node server.js

# macOS / Linux
PORT=9000 node server.js
```

## 仕組み

**5 秒**ごと（変更可）にループし、次の処理を行います：

```
① 取行情          从币安拉最新价、ATR 波动率、K 线
      ↓
② 算钱            资金基数 = 分配资金 + 这个机器人累计赚到的钱
      ↓
③ 算计划          首笔多少、加仓几次、每层多少、止盈价多少、止损价多少
      ↓
④ 做决策          现在是该开首笔？该加仓？该止盈？该止损？还是什么都不做？
      ↓
⑤ 执行            模拟盘：本地记账   实盘：真的发单到币安
      ↓
⑥ 落库            写订单、写事件、记权益曲线
```

### 3 つの重要な設計

**1. 価格アンカー（anchorPrice）**
計画が一度生成されると、買い増しのトリガー価格は固定され、相場が上下してもずれません。
「完全決済」のあとにだけアンカーを取り直し、新しいラウンドを始めます。

**2. 利確価格は常に「現在の実際の保有平均単価」から即時計算**
`利確価格 = 現在の平均単価 × (1 + 利確幅)`

なぜ「現在」を強調するのか？ 「6 層まで積んだ後の予測平均単価」で計算すると、1 筆しか建てていないとき、
その予測平均単価はまだずっと下にあり（ロングの場合）、現価格はとっくにそれを上回っています —— 結果は**建玉直後に利確**となり、手数料を無駄に払うだけです。
これは本プロジェクトが初期に踏んだ実際の落とし穴で、現在は現在値での計算に改めています。

**3. 層数は「最大で何回買い増せるか」であり、「最初に何層建てるか」ではない**
`maxLayers = 6` の意味は：まず 1 筆建て、その後は相場が `间距`(間隔) だけ動くたびに 1 回買い増し、最大 6 筆まで。
最初から 6 筆すべてを建てるわけではありません。

## パラメータの調整

13 個のパラメータはすべて中国語のラベルで、フォームに直接入力します。既定値は「中立」な設定一式です：

| パラメータ | 意味 | 既定値 |
|---|---|---|
| 交易方向(売買方向) | 双向(双方向) / 只做多(ロングのみ) / 只做空(ショートのみ) | 双向 |
| 分配给这个机器人的资金(このボットへの割当資金) | ボットが動かせる最大の元手（USDT） | 100 |
| 第一笔保证金占分配资金的比例(1 筆目の証拠金が割当資金に占める割合) | 1 筆目で元手の何 % を使うか | 1% |
| 杠杆倍数(レバレッジ倍率) | 先物のレバレッジ | 20x |
| 每加一次仓，金额是上一次的几倍(買い増しごとに金額を前回の何倍にするか) | 買い増しの増加倍率 | 1.5 |
| 加仓间距(買い増し間隔) | 価格が平均単価から何 % 動いたら 1 回買い増すか | 1% |
| 最多加仓几次(最大買い増し回数) | 層数の上限 | 6 |
| 单方向最多投入多少钱(片方向の最大投入額) | 名目上限 = 割当資金 × この倍率 | 3 |
| 全部加满时，最多能亏分配资金的百分之几(すべて積み上がったとき、割当資金の何 % まで損失を許容するか) | リスク予算 | 35% |
| 止盈方式(利確方式) | 按均价(平均単価で全体) / 逐笔(1 筆ずつ) | 按均价 |
| 止盈幅度(利確幅) | 現在の平均単価に対して何 % 稼いだら逃げるか | 0.5% |
| 止损幅度(損切り幅) | 現在の平均単価に対して何 % 負けたら損失を認めるか | 5% |
| 每多久判断一次(判断の頻度) | 意思決定の周期 | 5 分 |

### 3 つの参考構成

| | 保守的 | 中立（既定） | 積極的 |
|---|---|---|---|
| 1 筆目の証拠金比率 | 0.5% | 1% | 2% |
| レバレッジ | 5x | 20x | 50x |
| 買い増し間隔 | 2% | 1% | 0.5% |
| 買い増し回数の上限 | 4 回 | 6 回 | 10 回 |
| 片方向の名目上限 | 2 倍 | 3 倍 | 6 倍 |
| 最大損失 | 20% | 35% | 50% |

> **積極的な設定は「もっと儲かる」ではなく「もっと早くゼロに砕ける」です。** 初心者は既定値のまま、ペーパーモードで 2 週間走らせてから調整を語りましょう。

各パラメータを大きく / 小さくすると何が起きるかは [docs/STRATEGY.md](docs/ja/STRATEGY.md) を参照してください。

## ペーパーモードと実弾モード

| | 模拟盘（paper）(ペーパーモード) | 实盘（live）(実弾モード) |
|---|---|---|
| API Key が必要か | 不要 | **必ず**先に追加して検証すること |
| お金 | ローカルの仮想残高、自由に変更可 | バイナンス口座の実際のお金 |
| 約定 | ローカル約定。手数料 0.05% + スリッページ 0.02% を差し引く | 実際の成行注文 |
| リスク | ゼロ | **本当にお金を失います** |
| 用途 | 画面に慣れる、パラメータを練習する、ロジックを検証する | 結果を完全に理解しているときだけ |

### 実弾モードを開く 2 つの関門

1. **検証済みの API Key が必須** —— 未設定なら起動を拒否し、中国語のメッセージを返します。
2. **起動時に環境変数 `LIVE_TRADING=1` を設定することが必須** —— そうでなければ Key が設定済みでも実弾ボットは止められ、相場を読むだけで発注しません。

```powershell
# Windows PowerShell
$env:LIVE_TRADING=1; node server.js

# macOS / Linux
LIVE_TRADING=1 node server.js
```

### ボットはこの銘柄の全ポジションを引き継ぎます

バイナンスの両建てポジションは**口座レベルで集約**されます —— API は「この銘柄のロングが 4.37 枚」としか返さず、
どの注文がボット由来で、どれがあなたの手動なのかは区別できません。

**1.0.2 から引き継ぎ（テイクオーバー）モードに変更しました**（ご要望に従って）：ボットが起動すると、その取引ペアの**全ポジション**を引き継ぎます。

| タイミング | 動作 |
|---|---|
| 起動時にすでにポジションがある（手動で建てた分も、古いボットが残した分も含む） | **すべてボットの台帳に登録**し、平均建値は取引所の実際の平均値から逆算。**買い増しはせず**、実際の平均値から計算した利確価格に達したら**その方向を丸ごと一度に決済** |
| 全部決済した後 | 引き継ぎ状態が自動解除され、**第 1 層を建て直し**、以降はパラメータどおり買い増し／利確 |
| あなたが手動で減らした | 台帳を実際の数量に合わせて縮小（存在しないポジションを決済しに行かない） |
| あなたが手動で台帳以上に増やした | 超過分も同じく台帳に引き継ぐ |

重要なポイント：

- **利確価格は取引所の実際の平均建値を使います**（ボットが予測した平均値ではありません）。だからこそ「到達したら全決済」が本当の利確になります。
- 引き継ぎ中は**買い増ししません** —— 利確価格に達する前に下へ買い増すと、リスクが大きくなるだけだからです。
- 引き継ぎ中も**ハードな損切りで保護**され、利確だけを待つわけではありません。
- 利確モードを「1 筆ずつ利確」にしていても、引き継ぎ中は強制的に**その方向を丸ごと決済**し、一部だけ決済することはありません。

突き合わせイベント（詳細ページの「イベント」で確認できます）：

> 接管：多单已有 3.4 张不是机器人开的仓位，已全部接管（实际均价 0.939206）。接管仓位不加仓，等止盈价 0.955000 一次性全平。
> （引き継ぎ：ロング 3.4 枚はボットが建てたものではありませんが、すべて引き継ぎました（実際の平均建値 0.939206）。引き継いだポジションは買い増しせず、利確価格 0.955000 で一度に全決済します。）

> 对账：多单在交易所已归零，机器人账本也同步清空。下一次 tick 会重新建第一层。
> （突き合わせ：ロングは取引所でゼロになり、ボットの台帳も同期して空になりました。次の tick で第 1 層を建て直します。）

## セキュリティ設計

| 項目 | 対応 |
|---|---|
| API Key の保存 | **AES-256-GCM で暗号化**して DB に保存。どの API も平文を返さず、画面にはマスク値だけを表示 |
| 暗号化マスターキー | `data/master.key`（自動生成、権限 0600）。環境変数 `BT_MASTER_KEY` でも指定可 |
| ログインパスワード | **scrypt + ユーザーごとのランダムソルト**。検証は `timingSafeEqual` でタイミング攻撃を防止 |
| セッション | `HttpOnly; SameSite=Lax` Cookie、7 日で失効、サーバー側からも削除可 |
| ログイン試行制限 | 同一ユーザー名で 5 回/分 |
| SQL | すべてパラメータバインド、文字列連結なし |
| 権限 | すべての書き込み API でリソースの所有者を検証。ユーザー A は B のボットを変更できない |
| ネットワーク露出 | **既定では `127.0.0.1` のみ待ち受け**、外部には公開しない |
| 実弾発注 | **既定でオフ**、`LIVE_TRADING=1` で解放 |
| 二重発注 | 決定的な `clientOrderId`。ネットワークタイムアウトで再送しても取引所が重複 ID として拒否 |

> ⚠️ **`data/master.key` を失うと、保存済みの API Key は復号できません。**
> `data/app.db` をバックアップするときは**必ず master.key とセットで**バックアップしてください。DB だけのバックアップは無意味です。

セキュリティポリシーの全文は [SECURITY.md](SECURITY.ja.md)。

## リスクについて必ず読んでください

これは**現実に存在し、お金を失う取引ツール**です。実弾モードに進むかどうかを決める前に、この段落を最後まで読んでください。

1. **先物は証拠金取引であり、強制ロスカットがあります。** 20 倍レバレッジでは、価格が 5% 逆行するだけで元手をすべて失う可能性があります。レバレッジが高いほどゼロになりやすい。
2. **「買い増しでコストを下げる」は一方向の相場で延々と含み損を抱えます。** この戦略の核心的な前提は「価格は反発する」です。
   ある銘柄が長期の一方向下落に入れば、買い増しは**より大きく、より早く**損失を増やすだけです。層を使い切るか損切りに当たるまで続きます。
3. **パラメータが積極的なほど、ゼロになるのが早い。** 高レバレッジ + 狭い間隔 + 多い層数 = ごく短時間で爆発するレシピ。
4. **手数料は継続的な摩擦コストです。** 建玉と決済のたびに手数料がかかり、利確幅を小さく設定すると（例えば 0.1%）、
   手数料が利益の大部分を食うか、逆に赤字になります。
5. **強制ロスカット価格は概算値**で、実際は取引所が返す値が優先です。
6. **本プロジェクトは Apache-2.0 に基づき「現状のまま」提供され、いかなる保証も伴いません。** 作者は本プロジェクトの利用によって生じた資金の損失に責任を負いません。

**実弾モードに進むつもりなら、この順序を守ってください：**

1. ペーパーモードで**最低 2 週間**走らせ、ロジックとパラメータを自分が受け入れられるか確認する。
2. 実弾はまず**完全に失っても構わないごく少額**で 1 週間。
3. API Key は**先物取引の権限だけを有効にし、出金権限は絶対に付けない**。可能なら IP ホワイトリストを設定する。
4. 毎日 1 回は口座を確認し、ボットの挙動が想定どおりか確かめる。
5. 少しでもおかしいと感じたら、まず**ボットを停止**し、それから分析する。

## よくある質問

**Q：`npm install` は必要ですか？**
不要です。サードパーティ依存ゼロで、Node の組み込みモジュールだけを使っています。

**Q：Node のバージョンはどのくらい必要？ なぜ 22.5 未満ではダメ？**
本プロジェクトはデータベースに `node:sqlite` を使っており、このモジュールは **Node 22.5** から提供されています。それ未満では起動時にエラーになります。

**Q：公開サーバーに置いてスマホからアクセスできますか？**
できますが、**必ず HTTPS リバースプロキシを経由**し、ポートをそのまま公衆網に晒さないでください。
詳しくは [DEPLOY.md](DEPLOY.ja.md)。

**Q：ペーパーモードの価格は本物ですか？**
本物です。既定ではバイナンス `fapi.binance.com` に直接接続してリアルタイム相場を取得します。あなたのネットワークからバイナンスに到達できないときだけ、ローカルのシミュレート価格へ自動的に切り替え、画面にその旨を表示します。

**Q：ボット作成時に「参数不可行」(パラメータが実行不可能) と出るのはなぜ？**
多くの場合、「割当資金 × 1 筆目の比率 × レバレッジ」で計算した 1 筆目の金額が小さすぎて、取引所の最小発注額を下回っています。
メッセージには、どのパラメータをいくつにすればよいかが直接書かれます。詳しくは [docs/FAQ.md](docs/ja/FAQ.md)。

**Q：ボットがずっと動きません。**
正常です。価格が計画した位置まで来るのを待っています。「详情」(詳細) ページでイベントログを見れば、各ステップの判断が分かります。

その他の質問は [docs/FAQ.md](docs/ja/FAQ.md)。
