# 币安量化终端 · U 本位永续自动化交易机器人平台

一个**零第三方依赖**的本地 Web 平台（Node 24 内置模块实现），用于运行基于「账户权益 × 无量纲系数」的自动网格加仓机器人。

- **实时行情**：默认直连币安 `fapi.binance.com` 拉取全市场报价，30 个高成交额标的按成交额自动排序；断网时自动降级为本地模拟行情并在页面提示。
- **模拟模式**：本地撮合，不需要 API Key，随时可试；模拟盘余额可在「账户」页随时自定义（默认 100 USDT）。
- **实盘模式**：填写币安 U 本位合约 API Key 后，实时调用真实账户与下单接口。
- 参数全部由前端表单自定义，也有推荐默认值；下单金额**永不写死**，始终按实时权益等比缩放。

## 快速开始

```bash
cd B:\biance_trae
node server.js
```

然后用浏览器打开 **http://127.0.0.1:8787** ，注册一个账号即可使用。

> 首次启动会自动创建 `data/app.db`（SQLite）和 `data/master.key`（API Key 加密主密钥，权限 0600）。
> **`data/master.key` 是解密 API Key 的唯一钥匙，请务必备份，丢失后已存的 Key 无法解密。**

### 可选环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `HOST` | `127.0.0.1` | 监听地址（服务器/局域网访问改 `0.0.0.0`） |
| `BASE_PATH` | 空 | 子路径部署前缀，例如 `/biance_trae`。设置后后端会自动从请求路径剥掉该前缀，并把登录 Cookie 的 Path 设为该前缀，不会干扰同域其他站点 |
| `BT_MASTER_KEY` | 自动生成 | 64 位 hex，主加密密钥；设置了就不读 `data/master.key` |
| `BINANCE_BASE_URL` | `https://fapi.binance.com` | 币安 U 本位合约 REST 根地址 |
| `BINANCE_FEED` | `live` | 行情源：`live`=币安实时，`mock`=本地模拟 |
| `LIVE_TRADING` | 未设置（=关闭） | 实盘下单安全闸；设 `1` 才允许向真实账户发单 |
| `BINANCE_TIMEOUT_MS` | `8000` | 币安请求超时 |
| `TICK_INTERVAL_MS` | `5000` | 机器人决策与模拟行情推进间隔 |

```powershell
# PowerShell 示例：换个端口启动
$env:PORT=9000; node server.js
```

### 模拟 / 实盘切换

- 新建机器人时选择 `mode`。`paper` 全程本地模拟；`live` 走真实币安接口。
- `live` 模式**必须**先在「API Key」页配置并验证密钥，否则启动会被拒绝并给出中文提示。
- 行情源默认走币安实时行情；设 `BINANCE_FEED=mock` 可强制用本地模拟行情（离线开发/演示用）。
- 详情页与账户页顶部有模式开关，可随时查看两种口径下的数据。

## 策略说明（这是本平台的核心）

用户原始想法：专注一个币种、全仓、以总资金的一定比例做多和做空各一份，价格每涨/跌一定比例就止盈一侧、加仓另一侧。

平台把它抽象成**完全无量纲**的参数化模型——同一套参数在 100U 和 10000U 账户上行为完全等比，**代码里没有任何硬编码的 U 数**：

| 参数 | 含义 | 默认 |
|---|---|---|
| `direction` | `dual` 双边 / `long` 仅做多 | `dual` |
| `k` | 首层保证金占权益比例 | 1% |
| `leverage` | 杠杆 | 20x |
| `kMax` | 总名义 / 权益 上限 | 3.0 |
| `dMax` | 满仓最大浮亏占权益比例 | 35% |
| `beta` | 网格间距 = β × ATR | 0.4 |
| `trendGateAtr` | 趋势闸门（× ATR） | 2 |
| `maxLayers` | 层数硬上限 | 10 |
| `tpMode` | 单层止盈 / 均价止盈 | 单层 |
| `stopAtr` | 硬止损 = 末层 − stopAtr × ATR | 2 |
| `interval` | 决策周期 | 1h |
| `initialCapital` | 模拟初始资金 | 100 USDT |

求解链：

1. `间距 g = clamp(β × ATR, 最小跳动, 3%)`
2. `首层保证金 m1 = k × 权益`，`首层名义 = m1 × leverage`
3. 公比 `r` 由等比数列求和反解：`(rⁿ−1)/(r−1) = kMax / (k × leverage)`
4. 层数 `n` 取满足三条约束的**最大**整数：总名义 ≤ `kMax × 权益`；满仓浮亏 ≤ `dMax × 权益`；估算强平价 ≤ 末层价 × (1 − 2×ATR)
5. 各层名义 `= m1 × leverage × rⁱ`
6. 止盈：单层模式为该层入场价 × (1+g)；均价模式为满仓均价 × (1+g)
7. 止损：`max(末层价 × (1 − stopAtr×ATR), 估算强平价 × 1.15)`

`direction = dual` 时，空头腿是多头腿的**完整镜像**，参与同一套约束判定：

- 空头各层入场价 `= 现价 × (1+g)ⁱ`（价格向上时逐层加空），名义金额与多头同层相同。
- 空头止盈 `= 该层入场价 × (1−g)`，空头止损 `= min(末层价 × (1 + stopAtr×ATR), 估算强平价 ÷ 1.15)`。
- 三条约束取两腿中**更差**的一侧：`max(多头止损浮亏, 空头止损浮亏) ≤ dMax × 权益`，且两侧强平价都必须离各自末层至少 2×ATR。

> 早期版本只算了多头腿，空头误用多头的止损价，导致空单一开仓就被判定为触发止损、反复开平。该问题已修复（solver 输出 `stopPriceShort / tpPriceShort / liqPriceShort`，engine 按方向取对应值）。

**强平价是近似估算**，实际以币安返回为准。上实盘前务必先用最小资金验证。

## 安全说明

- API Key / Secret 用 **AES-256-GCM** 加密后落库，任何接口都不回传明文，前端只显示脱敏值。
- 密码用 **scrypt + 每用户随机盐**，校验走 `timingSafeEqual`。
- 会话 Cookie：`HttpOnly; SameSite=Lax; Path=/`。
- 所有 SQL 参数绑定，所有写接口校验资源归属。
- 登录失败限流：同用户名 5 次 / 分钟。
- 平台默认只监听 `127.0.0.1`，不对外暴露。
- **实盘下单总开关默认关闭**：未设 `LIVE_TRADING=1` 时，即使 API Key 已验证，实盘机器人也会被拒绝启动（`LIVE_DISABLED`），绝不向真实账户发单。

### 实盘仓位是怎么界定的（重要）

币安 U 本位**双向持仓**模式下，同一个交易对的「多头」是**账户级聚合**的：`positionRisk`
只会告诉你「HYPEUSDT 多单 4.37 张」，分不清其中哪些是机器人开的、哪些是你手动开的。

本平台的做法是给每个实盘机器人单独记一本**持仓账本**（存在该机器人的 `state_json.liveLegs`）：

- 机器人每次开仓成功，把这一笔（数量、成交均价、层数）记进账本；
- 每次平仓，按数量从账本里扣掉；
- 每个 tick 与交易所实际持仓对账：
  - 交易所数量 **多于**账本 → 多出来的认定是**手动仓**，机器人在持仓里标「手动」，**绝不平它**；
  - 交易所数量 **少于**账本 → 你手动平掉了一部分，账本按比例缩减，不会去平不存在的仓位；
  - 你在币安上把仓位全平了 → 账本清零，机器人下个 tick 发现没仓位就重新从第 1 笔开始。

所以：**手动仓位和机器人仓位可以共存**，机器人只管理自己开的那部分。
风险提示：平仓时用的是市价 `reduceOnly` 单，如果手动仓和机器人仓方向相同，
币安会先从同一个持仓里扣减，账面上看是「一起变少」，这是交易所的聚合机制，不影响盈亏归属。

### 上实盘前的必做清单

1. 先在**币安测试网**或**最小资金**账户跑通。
2. API Key 只开「合约交易」权限，**不要开提现权限**，有条件就绑定 IP 白名单。
3. 确认 `firstPct`（第一笔保证金占比）、`totalPct`（单方向最多投入）、`maxLossPct`（最坏亏损上限）、`leverage` 的组合在自己能承受的回撤范围内。
4. 启动实盘机器人时会自动把该交易对的杠杆设置成参数里的值，并写一条事件日志。
5. 本机网络无法访问币安域名时，行情会自动降级为模拟值并在页面明确提示，不会静默下单或伪造数据。

## 常见问题

**Q：打开页面提示「前端资源尚未就绪」？**
A：`src/static/` 下缺少前端文件，检查是否完整拷贝了项目。

**Q：实盘账户页显示「未配置 API Key 或网络不可达」？**
A：两种情况——(1) 还没在 API Key 页添加并验证密钥；(2) 本机网络访问不了币安域名（中国大陆常见）。平台会降级展示，不会崩溃。

**Q：忘记密码？**
A：直接删除 `data/app.db` 里对应的 `users` 记录，或整个删除 `data/` 重新初始化（**会清空所有机器人和历史**）。
